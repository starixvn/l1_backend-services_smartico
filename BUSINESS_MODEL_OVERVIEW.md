#### **Understanding Player Identity (IMPORTANT!)**

Before integrating, you need to understand how Smartico uniquely identifies and tracks players in a multi-tenant environment.

```
┌─────────────────────────────────────────────────────────────────┐
│              HOW SMARTICO IDENTIFIES PLAYERS                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  UNIQUE PLAYER IDENTIFIER = operatorId + playerId               │
│                                                                 │
│  Example:                                                       │
│  - Operator: "lucky-casino"                                     │
│  - Player:   "player_123"                                       │
│  = Smartico ID: "lucky-casino:player_123"                       │
│                                                                 │
│  This ensures:                                                  │
│  ✓ Players are unique per operator                              │
│  ✓ Same playerId can exist in different operators               │
│  ✓ Data never mixes between operators                           │
│  ✓ Complete multi-tenancy isolation                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**How Smartico Stores Players (Database):**

```sql
-- Smartico's player table uses a composite primary key
CREATE TABLE players (
  -- Composite unique identifier
  operator_id VARCHAR(100) NOT NULL,
  player_id VARCHAR(100) NOT NULL,

  -- Player profile
  username VARCHAR(100),
  tier VARCHAR(50),
  currency VARCHAR(10),
  country VARCHAR(10),
  language VARCHAR(10),
  registered_at TIMESTAMPTZ,

  -- Gamification data (managed by Smartico)
  total_missions_completed INT DEFAULT 0,
  total_bonuses_claimed INT DEFAULT 0,
  total_points INT DEFAULT 0,
  level INT DEFAULT 1,

  -- Timestamps
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),

  -- Composite primary key ensures uniqueness
  PRIMARY KEY (operator_id, player_id)
);

-- Example data:
-- operator_id      | player_id  | username       | tier | currency
-- lucky-casino     | player_123 | lucky_player   | vip  | USD
-- lucky-casino     | player_456 | slot_master    | gold | EUR
-- betmax           | player_123 | betmax_user    | new  | USD  ← Same ID, different operator!
```

**Why This Works - Three Key Scenarios:**

```
SCENARIO 1: Same player ID in different operators
─────────────────────────────────────────────────
Operator A: "lucky-casino" has player_123
Operator B: "betmax" also has player_123

These are DIFFERENT players because:
- lucky-casino:player_123 ≠ betmax:player_123
- Data never mixes
- Each has separate missions, bonuses, progress

SCENARIO 2: Tracking player activity
─────────────────────────────────────
When you send event:
{
  "event": "bet_placed",
  "playerId": "player_123",
  "amount": 50
}

Smartico receives it via authenticated API (your API key identifies operator)
→ Knows this is from "lucky-casino"
→ Updates lucky-casino:player_123
→ NOT betmax:player_123

SCENARIO 3: Widget authentication
──────────────────────────────────
JWT token contains:
{
  "operatorId": "lucky-casino",
  "playerId": "player_123"
}

Widget loads:
→ Smartico extracts both fields
→ Queries: SELECT * FROM players WHERE operator_id='lucky-casino' AND player_id='player_123'
→ Loads correct player profile
→ Shows personalized dashboard
```

#### **Player Profile Synchronization**

Now that you understand how players are identified, let's look at how to sync their profiles.

**Player Identity Flow:**

```
┌─────────────────────────────────────────────────────────────────┐
│                   PLAYER PROFILE SYNC FLOW                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  FIRST TIME (Player Registration):                              │
│  ─────────────────────────────                                  │
│  1. Player registers at YOUR casino                             │
│     → Your system creates player_123                            │
│                                                                 │
│  2. You send initial profile to Smartico                        │
│     POST /api/v1/players/sync                                   │
│     {                                                            │
│       "operatorId": "lucky-casino",                             │
│       "playerId": "player_123",                                 │
│       "profile": { ... }                                        │
│     }                                                            │
│                                                                 │
│  3. Smartico creates player record                              │
│     → Stores: lucky-casino:player_123                           │
│     → Status: Active                                            │
│     → Profile: { tier, currency, etc }                          │
│                                                                 │
│  ─────────────────────────────                                  │
│  EVERY LOGIN (Session Authentication):                           │
│  ─────────────────────────────                                  │
│  4. Player logs into YOUR casino                                │
│     → Your system authenticates player_123                      │
│                                                                 │
│  5. Your backend generates JWT token                            │
│     → Includes: operatorId + playerId                           │
│     → Token signs with shared secret                            │
│                                                                 │
│  6. Widget loads with token                                     │
│     → Smartico validates token                                  │
│     → Extracts: lucky-casino:player_123                         │
│     → Loads player profile from database                        │
│                                                                 │
│  7. Player sees their personalized dashboard                    │
│     → All missions, bonuses specific to this player             │
│     → Progress tracked by lucky-casino:player_123               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**Option 1: JWT Token (Recommended - Most Secure)**

```javascript
// Your backend generates JWT when player logs in
const jwt = require('jsonwebtoken');

const playerToken = jwt.sign({
  // Required fields
  playerId: 'player_123',          // Your internal player ID
  operatorId: 'lucky-casino',      // Your operator ID

  // Optional but recommended
  email: 'player@example.com',     // Hashed or pseudonymized
  username: 'lucky_player',        // Display name
  tier: 'vip',                     // bronze, silver, gold, vip
  currency: 'USD',                 // Player's currency
  country: 'US',                   // For compliance
  language: 'en',                  // Preferred language
  registeredAt: '2024-01-15',      // Registration date

  // Custom attributes (for segmentation)
  custom: {
    favGameType: 'slots',
    vipLevel: 3,
    preferredProvider: 'NetEnt'
  }
},
process.env.SMARTICO_SECRET_KEY,  // Shared secret
{ expiresIn: '24h' });

// Pass to widget
res.render('dashboard', { playerToken });
```

**Player Profile Fields:**

| Field | Required | Description | Example |
|-------|----------|-------------|---------|
| `playerId` | ✅ | Your internal player ID (never changes) | `player_123` |
| `operatorId` | ✅ | Your operator ID | `lucky-casino` |
| `email` | ⚠️ | Hashed email (for uniqueness, not communication) | `hash(email)` |
| `username` | ⚠️ | Display name | `lucky_player` |
| `tier` | ⚠️ | Player tier/VIP level | `vip`, `gold`, `silver` |
| `currency` | ⚠️ | Player's currency | `USD`, `EUR`, `GBP` |
| `country` | ⚠️ | Country code (for compliance) | `US`, `GB`, `CA` |
| `language` | ⚠️ | Preferred language | `en`, `es`, `de` |
| `registeredAt` | ❌ | When player registered | `2024-01-15T10:30:00Z` |
| `custom.*` | ❌ | Any custom attributes for segmentation | `{ vipLevel: 3 }` |

⚠️ = Recommended for better personalization
❌ = Optional

**Privacy & Security:**

```
✅ DO:
  - Use hashed/pseudonymized identifiers
  - Send minimal required data
  - Use HTTPS only
  - Rotate secrets regularly
  - Encrypt sensitive fields

❌ DON'T:
  - Send raw email addresses (hash them)
  - Send personal information (name, address, phone)
  - Send payment information
  - Send passwords or credentials
  - Store data you don't need
```
